Section 01

Project Overview & Executive Summary

NexaVoice is a full-stack, AI-powered voice calling platform designed for the Indian Real Estate industry. It automates outbound sales calls to prospective property buyers (leads) using an intelligent AI agent that can have natural, persuasive conversations in English and Hinglish. The platform replaces human cold-calling operations by combining real-time speech recognition, large language model intelligence, and ultra-realistic text-to-speech voice synthesis.

What Does NexaVoice Do?

  1. Imports Leads from Salesforce CRM or CSV files into its local database
  2. Dispatches AI Voice Calls to leads via a connected Android device (telephony gateway)
  3. Runs a real-time AI conversation — the AI speaks naturally, handles objections, recommends properties, and extracts CRM data automatically
  4. Records everything — full conversation transcripts, call recordings (stored in AWS S3), and call analytics
  5. Auto-updates the CRM — detected city preference, budget, bedrooms, and intent are automatically written back to the lead record
  6. Provides a Supervisor Console — supervisors can monitor live calls, see real-time transcripts, and "whisper" instructions to the AI mid-call

Step-by-Step Breakdown

Step 1 — Call Dispatch

Supervisor triggers a call from the React dashboard. The backend creates a Call record (status: SCHEDULED) linked to the target Lead, then broadcasts a CALL_ASSIGNED event via WebSocket to all connected mobile devices.

Step 2 — Phone Call & WebSocket

The Flutter app receives the assignment, dials the lead's phone number using the native Android dialer, and simultaneously opens a realtime WebSocket connection to the backend at /realtime/call/{call_id}.

Step 3 — Deepgram STT Initialization

The backend creates an AICallOrchestrator which establishes a live WebSocket connection to Deepgram's Nova-2 model. Configuration: language=hi (Hindi/Hinglish), 16kHz linear16 encoding, VAD + smart formatting enabled.

Step 4 — AI Welcome Greeting

After a 1.5s delay for the call line to settle, the AI generates a personalized intro greeting using the active VoiceAgent's first_message template (with {lead_name} and {city} placeholders). ElevenLabs converts this to speech and sends the audio bytes back through the WebSocket.

Step 5 — Real-Time Conversation Loop

Audio bytes stream continuously from the phone → Flutter → Backend → Deepgram. When Deepgram returns a final transcript, the AI engine fires: Save message → Gemini AI (CRM extract + reply) → Update Lead → ElevenLabs TTS → Send audio back. This loop repeats for every customer utterance.

Step 6 — Call Completion

When the WebSocket disconnects (call ends), the orchestrator closes the Deepgram stream, compiles all audio chunks into a WAV file, uploads to AWS S3, updates the Call record with the final transcript + recording URL, and broadcasts CALL_ENDED to all clients.

Key Flutter Services

🔌 Device Service

Registers the Android device with the backend on app startup. Sends device info (model, OS version, unique ID) and maintains a persistent WebSocket connection to receive call assignments.

🎵 Realtime Audio Service

Manages the bidirectional audio stream between the phone's microphone/speaker and the backend WebSocket. Sends raw PCM audio chunks and receives AI voice audio for playback.

📞 Call State Service

Manages the state machine for call lifecycle (IDLE → RINGING → ACTIVE → ENDED). Listens for incoming assignments and coordinates with Native Phone Service and Audio Service.

🌐 WebRTC Voice Service

Alternative audio transport using LiveKit WebRTC for low-latency audio streaming. Provides better audio quality and reduced latency compared to raw WebSocket audio.

State Management

The app uses Flutter Riverpod for state management and GoRouter for declarative routing. HTTP communication uses the Dio client with interceptors for JWT token injection.

💡 Mock Sandbox Mode
When Salesforce credentials are not configured, the system automatically falls back to a "Developer Sandbox" mode with realistic mock data. This allows testing the full integration pipeline without a live Salesforce org.

How RAG Works During a Call

  1. Customer speaks — e.g., "What amenities does Skyline Towers have?"
  2. Deepgram transcribes the speech to text
  3. The text is embedded into a 768-dimension vector using text-embedding-004
  4. A cosine similarity search against document_chunks finds the top 3 most relevant knowledge snippets
  5. These snippets are injected into the Gemini prompt as "Verified Ground Truth Facts from Salesforce"
  6. Gemini uses these facts to generate an accurate, grounded response instead of hallucinating

Role-Based Access Control (RBAC)

The system uses a dynamic RBAC model where Roles have a JSONB permissions array. Each route can require specific permissions using the RequirePermissions dependency.

Default Permission Set

view_dashboard manage_properties manage_leads manage_calls manage_agents manage_devices view_logs manage_roles

Multi-Tenancy

The platform supports multi-tenancy at the database level. Each major entity (User, Lead, Property, Call, Role) has a tenant_id foreign key. The set_current_tenant_id() function is called after JWT validation to scope all subsequent database queries to the authenticated user's tenant.
